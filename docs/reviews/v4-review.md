Document walkthroughs and structural checks are recorded below. One owner-selected real-project variation has since been exercised in a fresh context; the six original fictional exercises and cross-tool adherence remain unverified. Source checks do not substitute for behavioural evidence.

### Source review — 2026-09-26

- The tool-entry adapters and attribution script are unchanged. Both uninitialised and initialised START routes retain canonical agreements and task-relevant memory; the optional guides are not mandatory startup reading.
- Local Markdown links outside template fences resolve; Markdown fences balance. The README start prompt retains one plain fence. Template links are intentionally relative to the project root described in the initialisation procedure.
- No project intent/current-memory files were created in the foundation template. No private case-study names or local filesystem paths were included in the candidate documentation.
- Agreements grew from 2,547 to 3,002 whitespace-separated words (455 added). This is a document-size measurement, not a token-cost or adherence result. Detailed examples and upgrade mechanics stay outside normal startup context.

## Additional behavioural evidence — 2026-10-28

The owner selected a real, newly initialised v3 concept project for a read-only variation of V6. One fresh-context Codex agent, without the parent discussion or evaluation criteria, used the candidate upgrade procedure to propose changes. It correctly distinguished the unpublished candidate from the evidenced v3 baseline, preserved local roles and task-specific authority, retained initialised project content, excluded evaluation documents from the project upgrade and deferred adoption/provenance changes until agreement. No unnecessary onboarding questions were asked.

All applicable criteria for this variation were met. Before/after file hashes and Git state confirmed both the target project and candidate remained unchanged during the trial. Private case details, exact source hashes and the assessment are retained in the owner's local review workspace rather than this distributable foundation. The tool used inherited model selection; its exact model identifier was not independently established.

This exercises only V6 with known provenance, not its unknown-baseline condition or V1–V5. There was no v3-only control or cross-tool comparison. It supports the proposal workflow in this case, not a claim of measured improvement over v3, completed adoption or universal adherence. The fictional exercises in the table above remain unrun.

## Local adoption check — 2026-10-28

After the proposal trial, the owner approved local adoption in the same pilot project. Six documentation files were updated. Verification confirmed exact adoption of the candidate agreements core, preservation of all non-provenance project choices and all other project files, ten active local links, balanced Markdown fences and a clean whitespace check. Source fingerprints identify the exact unpublished candidate used.

A second fresh-context reader correctly recovered the product purpose, local unpublished foundation status, task-specific permissions, undecided technology and next product step, and found no contradictory or broken startup guidance. The pilot changes remain local and uncommitted; this foundation release does not publish or otherwise change that project. The check does not establish cross-tool adherence or improvement over a v3-only control.

## Release decision

The owner requested commit and release as v4 after the reported checks and limitations, and will continue evaluating the pilot separately. The six original fictional exercises remain unrun; no universal behavioural guarantee is claimed. This is a documentation-only foundation release. Existing project upgrades remain separately scoped and reviewed; release authority does not extend to publishing the pilot or changing other projects.

The foundation remains an uninitialised template: no fictional project intent/current-memory files, tool choices, standing permissions or deployment defaults were introduced. Future projects record source provenance in their own agreements only during requested initialisation; existing projects follow the optional upgrade procedure.
